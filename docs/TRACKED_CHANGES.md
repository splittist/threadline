# Tracked Changes Extraction

This document describes the tracked changes extraction feature implemented in Threadline.

## Overview

The tracked changes extraction feature parses OOXML (Office Open XML) tracked changes from Word documents and extracts them into a normalized data structure. This enables users to see all edits, insertions, deletions, and moves made to a document.

## Supported Change Types

The implementation supports all four types of OOXML tracked changes:

1. **Insertions** (`<w:ins>`) - Text that was added to the document
2. **Deletions** (`<w:del>`) - Text that was removed from the document
3. **Move From** (`<w:moveFrom>`) - Text that was moved from one location
4. **Move To** (`<w:moveTo>`) - Text that was moved to another location

## Data Structure

Each tracked change is represented by the `TrackedChange` interface:

```typescript
interface TrackedChange {
  changeId: string           // Unique ID: docId + originalId
  docId: string             // Document this change belongs to
  type: ChangeType          // 'insertion' | 'deletion' | 'moveFrom' | 'moveTo'
  author: string            // Author who made the change
  timestamp: string         // ISO 8601 timestamp
  originalId: string        // Original w:id from OOXML
  changedText: string       // The text that was changed
  textBefore: string        // Context: text from paragraph(s) before
  textAfter: string         // Context: text from paragraph(s) after
  clausePath: string[]      // Clause path where change occurs (e.g., ["1", "Section 1"])
  paragraphId: string       // ID of paragraph containing the change
}
```

## Implementation Details

### XML Parsing

The implementation uses `fast-xml-parser` with specific configurations:
- Namespace prefixes are removed (`w:` → element name)
- Whitespace is preserved (`trimValues: false`)
- Text content is extracted from both `<w:t>` (regular text) and `<w:delText>` (deleted text)

### Context Extraction

Context windows provide surrounding text to help understand where a change occurred:
- **textBefore**: Text from 1 paragraph before the change (configurable)
- **textAfter**: Text from 1 paragraph after the change (configurable)

### Clause Path Linking

Each change is linked to its location in the document hierarchy:
1. Find the paragraph containing the change
2. Scan backwards to find the most recent heading
3. Extract the clause path from the heading hierarchy
4. Example: `["8", "Termination", "8.2", "Force Majeure"]`

### Timestamp Normalization

Timestamps are normalized to ISO 8601 format:
- Supports both `w:date` and `w16du:dateUtc` attributes
- Falls back to current timestamp if parsing fails
- Example: `2024-01-15T10:30:00.000Z`

### Change ID Generation

Unique change IDs are generated by combining:
- Document ID (docId)
- Original OOXML change ID (w:id attribute)
- Format: `{docId}-{originalId}`
- Example: `doc-123-5`

## Usage

### In Document Worker

Tracked changes are automatically extracted during document parsing:

```typescript
import { extractTrackedChanges } from '../utils/trackedChanges'

// After parsing document structure
const changes = extractTrackedChanges(
  documentXml,
  docId,
  hierarchy.paragraphs,
  headings
)

// Add to parsed document
const parsedDocument: ParsedDocument = {
  // ... other fields
  changes,
}
```

### Accessing Changes

Changes are available in the parsed document:

```typescript
const parsedDoc = await parseDocument(file)
const allChanges = parsedDoc.changes

// Filter by type
const insertions = allChanges.filter(c => c.type === 'insertion')
const deletions = allChanges.filter(c => c.type === 'deletion')

// Group by author
const byAuthor = allChanges.reduce((acc, change) => {
  if (!acc[change.author]) acc[change.author] = []
  acc[change.author].push(change)
  return acc
}, {} as Record<string, TrackedChange[]>)

// Group by clause path
const byClause = allChanges.reduce((acc, change) => {
  const key = change.clausePath.join(' > ')
  if (!acc[key]) acc[key] = []
  acc[key].push(change)
  return acc
}, {} as Record<string, TrackedChange[]>)
```

## Edge Cases Handled

1. **Missing Author**: Defaults to "Unknown"
2. **Missing Timestamp**: Uses current timestamp
3. **Multiple Changes in Paragraph**: All changes are extracted separately
4. **Changes at Document Boundaries**: Context windows handle start/end of document
5. **Nested Changes**: Each change is extracted independently
6. **Empty Changed Text**: Preserved as empty string (valid for complex formatting scenarios)

## Performance Considerations

- Parsing runs in a Web Worker to avoid blocking the UI
- Context extraction uses efficient array slicing
- Heading lookup uses recursive traversal with early exit
- No unnecessary DOM operations or re-parsing

## Future Enhancements

Potential improvements for future iterations:

4. **Change Conflict Detection**: Identify overlapping or conflicting changes
5. **Rich Text Support**: Preserve formatting in changed text
6. **Comment Association**: Link tracked changes to document comments
7. **Revision History**: Track multiple revisions of the same change
